目标是 `index.html` 的 `#settings-modal` 内 `#providers-list .card-name` 与 `#models-list .card-name`，对应 `css/features/settings-theme-skin.css` 第 282–318 行附近。模式为 **Operate**，仅评估已批准的名称表达 refinement，不扩展为设置页重设计。

## Design specificity

这是适合 CainFlow 的克制工具表达。产品面向管理自有 API 和模型的个人创作者，名称首先是反复辨认的配置身份，其次才是表单字段。粗细适中的标题文字、常显细底线、收起时直接聚焦的原生输入框，和展开后的 API 地址等完整表单形成了清楚分工。名称不需要增加装饰性品牌动作；产品特性来自高频配置的效率、中文长名与模型代码的兼容、七主题语义及稳定的状态层级。

两类名称使用相同交互语法，同时模型名允许比供应商名更宽，符合模型标识通常更长的实际内容。没有为了“独特”而破坏用户熟悉的文本编辑习惯。

当前重命名决策点是从两个供应商或三个模型中选择对象，没有观察到超过四个同级候选的决策点。页面上存在超过四个控件，并不等同于单次决策同时需要比较全部控件。大量真实配置的浏览、过滤和排序不在这个样本覆盖范围。

## Emotional journey

浏览阶段维持标题式安静表面；细底线提供“这里可以改”的预期。点击后出现主题焦点边框与插入符，能立即确认进入编辑。点名称不会同时展开配置，减少“只是想改名却打开一整块表单”的干扰。结束编辑和保存后的情绪终点没有实际操作证据，因此不推定保存成功体验已通过。

## 做得好的地方

1. **可编辑线索与表面轻重匹配。** 常态只留细底线，聚焦才出现轻完整边框，满足“标题式编辑”的目标，也避免每行常驻完整输入框造成的表单感。
2. **文字权重与占宽符合内容。** 14px/600 的名称在暗色、纸色和玻璃表面上均易扫读；模型名比供应商名更宽。窄窗长名截断后没有挤掉右侧操作。
3. **保持原交互分工。** 独立浏览器实看中，折叠供应商名与模型名都可直接聚焦；供应商卡片标题空白可独立展开及收起。拖动柄仍以独立对象呈现，未改成整行可拖的混合命中区。
