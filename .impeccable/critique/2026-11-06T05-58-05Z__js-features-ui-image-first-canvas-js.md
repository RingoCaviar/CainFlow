- 提示词与单行底栏形成清楚的编辑—配置—生成路径，二级菜单承担复杂参数。

## 优先问题

1. **[P1] 键盘打开菜单后，Tab绕过展开内容。** Enter打开参数页，接着Tab到模型，再到生成；不是全部控件不可访问，而是顺向操作路径未进入新内容。建议键盘打开时将焦点交给当前分组或首个控件，保留Esc返回入口。建议命令：`impeccable harden`。证据：`js/features/ui/image-first-canvas.js:323`、`:338`、`:758`及浏览器焦点序列。
2. **[P1] 多项控件名称无法区分。** 分辨率只叫“自动”，质量、背景等都叫“默认”；次数输入无程序化名称，系统提示词名称表现为字段ID。建议关联视觉label与真实操作控件，使用“分辨率：自动”“生成次数”等可访问名称。无需增加视觉标签行。建议命令：`impeccable harden`。证据：`js/nodes/node-dom-bindings.js:964`、`js/nodes/node-view-factory.js:461`及实时AX。
3. **[P1] 非默认生成次数在执行点不可见。** 隔离配置次数3，菜单关闭后按钮仍为“生成”。用户必须记住批次设置。建议次数大于1时显示“生成 ×3”或现有参数摘要中显示数量，保留单行底栏。未执行生成，不对实际费用作断言。建议命令：`impeccable clarify`。
4. **[P2] 模型页的导航位置不明确。** 菜单有参考、尺寸、更多三个页签，打开模型页时三项均未选中。建议模型使用独立紧凑菜单，或成为统一菜单的第四页签。A还观察到从参考页点击底栏模型首击仅关闭、次击才打开；该序列尚未由B复核，作为后续验证项，不断言根因。建议命令：`impeccable layout`。

## 认知负荷、情绪与使用者

主界面负荷低，深入配置后为中等：非默认次数需要工作记忆，模型页缺少位置提示。分辨率/质量有5个选项，但按需展开的领域选项不应仅因数量超过4就判为过载。

创作入口轻松，参数展开可控；模型导航短暂迷失，执行前缺少批次数量降低确认感，Esc回焦的收尾稳定。

- 新用户：普通浮层的尺寸摘要并不直接提示其中还有参考图与次数；打开后的空态说明有效。
- 高频用户：需要再次开菜单核对次数；跨入口切换效率值得优化。
- 键盘/读屏用户：Tab顺序与重复的“默认”名称是实际障碍，优先于外观润色。
