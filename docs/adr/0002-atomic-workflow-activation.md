# Make workflow activation atomic and identity-stable

CainFlow will route every active-workflow change through one deep workflow-activation module. Activations use latest-request-wins semantics, prepare the target before committing, keep background workflow runs alive across switches, and identify workflows with a stable workflow identity rather than their mutable name or path; this avoids interleaved canvas commits and prevents rename or folder moves from detaching runtime results, at the cost of migrating existing workflow documents lazily and temporarily rejecting rename or move operations for running workflows.

The saved workflow document is authoritative when its Workflow identity conflicts with session state; copying or saving as a new workflow creates a new identity. Legacy documents receive an identity in memory and session state when opened, but are written back only on an explicit save. An activation publishes its editor view, Workflow identity, and mutable label as one committed state, so preparation never exposes a new identity with the old canvas. Name-based fallback is confined to legacy migration adapters; normalized internal workflow references require a Workflow identity.

Within a project, the first loaded workflow retains a duplicated identity and a later external copy receives a new identity plus a visible pending-save state. Missing identities are normal lazy migrations; duplicate identities also produce a bounded diagnostic record, and ambiguous ownership stops activation instead of overwriting either workflow. The implementation keeps one indivisible committed activation state rather than independently writable active-name and active-identity fields. The current restriction on renaming or moving a running workflow remains product policy for this change, although the deep module must not rely on that restriction for correctness.

The workflow-activation module also owns the open-workflow identity index and every change that can affect its committed active state; workflow-list interaction and presentation remain outside the seam. Visible and detached editor views are the two concrete adapters at an internal editor-view seam, hiding DOM, ConnectionProjection handoff, and run-state restoration from activation semantics. Migration replaces writers rather than maintaining long-lived dual state: legacy active fields may temporarily be read-only projections, but all writes go through the committed activation state.

The external interface takes the domain-shaped `WorkflowDesk` form: common activation is expressed by `show`, session restoration remains a separate bulk operation, less common mutations use identity-bound workflow handles, and one immutable snapshot is the read surface. `show` accepts only a Workflow identity or an opaque selection issued by a document/migration adapter, never an arbitrary internal name. Copy and Save As remain behind this seam so the module allocates their new identities. The interface does not publish a general event subscription until a second real-time projection consumer justifies that additional seam.

Expected concurrency outcomes such as committed, already-visible, and superseded are structured results rather than errors. Load, identity-ownership, running-policy, editor-view commit, and recovery failures have explicit typed failure modes. If both the target commit and restoration of the previous view fail, the module atomically commits a safe-empty state, emits a bounded diagnostic record, and reports commit-recovery failure; diagnostic or finalize failures never undo an otherwise successful commit.

Tests use the `WorkflowDesk` interface as their primary surface and replace tests that reach through the old shallow activation, identity, or coordinator interfaces; independent editor-view adapter contract tests remain. Migration first establishes the immutable snapshot and identity index, then moves every active-state writer behind `WorkflowDesk` as one merge gate while legacy active fields become read-only projections. Session restoration, common activation, identity-bound mutations, and Background workflow run callers migrate in sequence; name fallback, the old coordinator interface, replaced tests, and finally the temporary projections are then removed.
