# 文件导入节点直接引用原文件

一个文件导入节点关联一份本地原文件。导入、展示和运行按需读取原位置，相关磁盘写入限于保存原文件引用及必要的文件信息。原位置的内容更新时，节点随之更新。文件丢失时，节点保留引用并提示用户。

这让外部维护的文件可以持续作为工作流输入。工作流的可用性取决于原位置与本机读取权限。CainFlow 管理的生成结果继续遵循 [ADR-0008](0008-shared-media-assets.md)。内置 Agent 和 Canvas MCP 通过 CainFlow 登记的标识使用文件，沿用 [ADR-0025](0025-scoped-canvas-automation.md) 的授权边界。

## 更新、缺失与运行

原路径重新可读后，节点自动恢复。同路径的文件替换视为内容更新。原文件被移动或改名后，用户可以在同一节点重新定位。原文件不可读期间，节点保留现有连线并显示原因。

外部修改会刷新节点展示，下一次运行读取最新内容。运行仍由现有工作流入口触发。同一次运行中的下游使用一致的文件版本。如果读取期间无法取得一致版本，受影响的分支提示重跑，独立分支继续运行。

## 保存与导出

在本机重新打开已保存的工作流时，恢复原文件引用。导出工作流时只带文件名、类型等重新定位所需的信息，接收方选择本机文件后建立新的原文件引用。

## 桌面操作与连线

首版在 Windows 桌面接收文件拖入、重新定位和打开原件。TXT 和 Markdown 在节点上只读展示，修改由外部应用保存到原件。PDF、Office 等复杂格式显示文件信息，点击后使用系统默认应用打开。

重新定位时保留节点和兼容的连线。更换文件时逐条检查下游是否支持新文件类型，标出冲突连线并说明原因。用户确认更换后，断开受影响的连线并提示结果，文件更换与断线可以一起撤销。因文件状态或下游模型变化产生的临时冲突保留原连线并发出警示，相关输入在运行前重新校验。

## 首版执行验收

首条端到端运行将 Markdown 原文作为文本连入智能对话节点的提问输入。TXT、图片和视频也必须通过兼容的端口到达下游。定向测试校验下游实际收到的类型、内容和文件版本，并验证原样预览或转发时沿用原文件引用。

PDF、Office 等复杂格式通过兼容下游的契约测试校验原件引用的传递和读取。具体模型的原件输入适配另行交付。编辑器、内置 Agent 和 Canvas MCP 在各自支持的运行范围内共用文件解析与输入校验，缺失或类型冲突时指出受影响的节点和端口。
