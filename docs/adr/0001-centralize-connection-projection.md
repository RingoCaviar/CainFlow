# Centralize the canvas connection projection

CainFlow will keep the workflow model authoritative while one deep `ConnectionProjection` module owns the derived connection-rendering projection, including frame coalescing, affected-path selection, caches, interaction settling, and alignment repair. Ordinary callers report geometry, appearance, topology, or Canvas interaction changes through dedicated intent methods; expensive whole-workflow and repair operations are isolated behind a maintenance capability, so callers cannot select full/dirty/immediate rendering strategies. We chose this over a generic change journal and a revisioned event stream because dedicated intents give the common caller a smaller interface without introducing a workflow revision solely for rendering.
