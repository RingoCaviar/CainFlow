# Protect undo media for the lifetime of its runtime session

Local issue: `cache-cleanup#005`.

Replace the metadata-only undo cache policy with temporary `session-undo` Media asset references. This is a runtime protection adapter under ADR-0011, not a persistent workflow owner or a revival of legacy `workflow-undo` references. A snapshot holds asset IDs, never image copies; ordinary cleanup cannot collect protected originals. Stack transfers protect the outgoing graph before applying a restore, and release the consumed record only after durable persistence. Eviction, redo invalidation and stack disposal release their own records. Agent result owners are independent.

Existing canvas mutation entry points require a synchronous history token. The browser therefore acknowledges a small local metadata protection transaction synchronously before mutation, instead of launching an unawaited promise and racing the deletion. Only this local transaction blocks; resource cleanup and release are asynchronous. A failed transaction prevents the mutation. Existing missing assets are reported and remain missing rather than being downloaded. A future async canvas-command migration can replace the transport without changing the session manager's protection contract.

Backend runtime, process, page and history identities isolate records. No heartbeat timeout expires a background page. Normal desktop close first awaits cancellation/settlement and workflow/session saves, then releases protection. A save failure keeps the window open unless the user explicitly discards unsaved changes. Backend exit releases only its runtime, with retries recorded in metadata. Recovery only expires another runtime after its process is confirmed dead; ambiguous process liveness or PID reuse retains protection conservatively. Closing a browser page cannot release other pages; if it cannot complete an acknowledged close, the backend retains its protection until service exit/recovery.

Released asset keys enter a durable cleanup queue. Bounded cleanup does not impose the ordinary five-minute age delay but still uses existing consumer checks, quarantine rules, integrity safety gates and atomic file deletion. Shared assets are retained, failed or suspended deletes stay pending, and database compaction remains best-effort with its existing thresholds. Physical deletion is not implied by reference release. Undo remains session-only and cannot be replayed after restarting.
