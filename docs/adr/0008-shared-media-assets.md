# Share generated media through locally managed Media assets

CainFlow persists every generated image and video as a content-addressed Media asset, then stores durable references from generation nodes and history records instead of storing independent media copies. A Media asset survives while at least one reference remains; deleting a node, workflow, history entry, or an automatically expired history entry only removes that owner's reference.

CainFlow reads a local Media asset before using any retained provider URL. A missing cached legacy video is a recoverable state, never a silent remote fallback: the user explicitly confirms Media asset recovery, observes progress and terminal state, and may cancel or retry. If cache capacity is exhausted and no unreferenced Media asset can be reclaimed, CainFlow retains the remote result URL and reports that it was not cached.

The storage backend owns the persistent reference index, cache quota, cleanup, and startup repair. The settings surface exposes actual cache use, the quota, and safe cleanup of unreferenced Media assets. This decision is separate from ADR-0003: media history is a user-facing result reference, not a Bounded diagnostic record.

The backend reference index is the sole authority for Media asset liveness. Creating a generated, imported, or derived result stores the Media asset and establishes its owner atomically before the result is exposed. Replacing an owner's reference list makes every new reference durable before releasing superseded references; interruption may leak a reference temporarily but must not make owned media collectible. Clients release explicit owners after the corresponding durable consumer deletion and never submit a visible-node or open-workflow snapshot to decide global liveness. Garbage collection reclaims only zero-reference Media assets.

Closing a workflow view does not release its owners. A persisted node or canvas deletion releases the affected workflow-node owners; deleting a workflow releases every workflow-node and workflow-import owner under its Workflow identity. Clearing history releases only history and history-thumbnail owners. Abandoned migration owners are reconciled on startup: CainFlow first attempts promotion from durable workflow data, then quarantines unassociated owners for a bounded grace period before reclaiming them with a diagnostic record.

Startup integrity checking compares four sources: durable workflow reference lists, the owner reference index, asset metadata, and physical files. A fast foreground pass validates the storage structure and critical references; if it detects risk, garbage collection remains disabled while a complete background scan runs. Editing and media browsing may continue. The resulting versioned Media asset integrity report is diagnostic state rather than a liveness authority.

CainFlow automatically repairs only evidence-preserving inconsistencies: missing formal owners for existing referenced media, duplicate idempotent references, and migration owners that can be associated unambiguously. Unassociated owners and unrecorded physical files are quarantined for a grace period before reclamation. A durable reference whose metadata or physical file is missing is never silently removed or remotely recovered. Ordered reference lists retain missing positions until the user explicitly recovers or removes them; present entries remain usable.

Media asset schema changes are forward-only, versioned, and idempotent. Before migration, CainFlow suspends storage writes and creates a verified Media asset migration backup: one recovery identity binds the database, parseable workflow documents, schema metadata, and a validated hash inventory of physical media. The backup remains outside garbage collection for at least 30 days and until an upgraded full integrity scan succeeds. Restoring it is never an in-place automatic downgrade; post-upgrade changes are exported first and the backup is validated in a separate location before an explicit switch.

A cross-process migration lock and Media asset storage epoch fence concurrent writers. Schema changes use short transactions; owner backfill commits by Workflow identity with a durable cursor, so interruption can resume idempotently. Migration completes only after schema changes, provable owner backfill, dangling-reference registration, integrity scanning, and backup association succeed; one transaction then records the schema version, minimum compatible version, and new epoch. Stale writers receive a retryable error and must reread ownership state. Older binaries cannot write upgraded storage.

Migration never guesses ownership or silently removes a dangling reference. Owners proven by durable consumer documents are backfilled; unresolved legacy assets receive a migration quarantine owner. Releasing that owner requires a full scan of every durable consumer source, an observation period of at least 30 days, and explicit user action or a declared retention policy. Expiry alone is insufficient. The frontend `keepKeys` snapshot immediately ceases to be liveness evidence; its legacy node endpoint remains temporarily observable and deprecated until supported stores have migrated, old calls are absent for two release cycles, and the minimum compatible version excludes old writers.

Garbage collection rolls out separately from migration: destructive legacy cleanup is disabled first, followed by audit-only candidate calculation, owner backfill, a full integrity scan, and at least seven days covering a representative usage cycle. Initial collection is an explicitly enabled, Workflow-scoped canary that excludes workflows with integrity warnings, migration quarantine owners, or active ownership transitions. Candidates move atomically into Media asset quarantine instead of being immediately deleted; conflicting restoration never overwrites a different file and uses content identity and a new content-addressed path. Collection candidates remain recoverable for at least 30 days.

Canary promotion is explicit and requires a clean observation cycle plus passing deletion, undo, history cleanup, import, concurrent-save, and crash-recovery scenarios. Early collection uses configurable conservative count and byte limits; exceeding either produces a report without moving files. Any index inconsistency, transactional or audit failure, quarantine failure, or abnormal candidate spike persistently disables collection without preventing workflow saving. A repair release resumes the forward migration rather than downgrading upgraded storage.

Migration and collection audits retain operation identity, phase, schema version, internal workflow and owner identities, redacted asset-key digests, counts, byte totals, hash-verification results, and failure stage. They exclude prompts, credentials, media content, complete URLs, and signed query parameters. Ordinary records remain for at least 90 days; records for quarantined assets remain with those assets, while migration summaries and backup associations are retained long-term.

Media asset safety is enforced by three shared test invariants: every durable consumer reference has a corresponding owner; no owned Media asset is a garbage-collection candidate; and an interrupted ownership transition may retain extra references but never lose a required reference. Tests use an independent oracle over workflow documents, owner rows, asset metadata, and physical files rather than trusting the production integrity scanner as their only authority.

The regression suite combines unit state-machine checks, real database and filesystem integration tests, and a small end-to-end set. It covers every owner kind alone and shared, every destructive entry point, partial multi-image damage, recovery failures, deterministic concurrency interleavings, and fault injection at each ownership, document, quarantine, audit, and migration commit boundary. A reference-model property suite generates reproducible operation sequences. Historical schema fixtures and independently constructed fixtures are permanent release gates; `keepKeys` inputs are explicitly tested to have no liveness effect.

Time-based behavior uses an injected UTC clock, and filesystem integration covers Windows plus a case-sensitive platform. Every test owns a validated isolated temporary root. Integrity scans bind a consistent storage epoch; a concurrently changed partition becomes stale and is rescanned rather than reported as damage or used for collection. Large scheduled fixtures measure scalability, but performance work may only paginate, increment, or rate-limit validation—it may not weaken safety checks.

Production observability reports owner distribution, zero-reference candidates, quarantine moves and restores, damage classes, pending transitions, migration progress, collection circuit-breaker reasons, and deprecated calls. Persistent state is the source for restart-time metric reconciliation. Operations are joined by local operation and parent-operation identifiers, storage epoch, internal consumer identity, owner kind, redacted asset digest, and stage. Diagnostic schemas are versioned; unknown newer reports are preserved but never interpreted for repair.

Successful transitions retain bounded recent detail and later aggregate by kind and outcome, while errors, migration, circuit breaking, and quarantine keep their complete redacted chain under the established retention rules. Saving may continue when non-destructive telemetry is degraded, but migration, quarantine, and physical deletion fail closed if their required audit record cannot be written. Diagnostic exports are previewable and exclude workflow content, media, prompts, credentials, paths, and complete URLs.

Concurrent Media asset ownership transitions are serialized per owner rather than per Workflow. Every owner has a monotonic revision, and every request compares its expected owner revision, Workflow document revision, and storage epoch. Conflicts never use last-write-wins or implicit document merging. A stable idempotency key binds the Workflow identity, owner kind and identity, logical operation identity, and target revision; replaying the same key with different content is an error, and an expired logical operation is rejected rather than treated as new.

A Media asset transition record progresses by compare-and-swap through `prepared`, `document_committed`, `owner_promoted`, `old_refs_released`, and `completed`, with `superseded` and `needs_reconciliation` recovery outcomes. New assets first receive a temporary transition owner; the complete target reference list is then saved under a document-revision CAS, the temporary owner is promoted, and only afterward are old references released. A crash may retain extra references. It must never release an asset still named by the durable document.

The durable workflow document expresses consumer intent, the owner index executes liveness, and the transition record supplies coordination evidence. Recovery uses all three. It automatically adds or retains protection when evidence is incomplete, but releases a temporary owner only after proving the operation was superseded, the target reference is absent from every durable consumer, and no committed stage remains recoverable. Time-to-live alone never releases a transition owner.

Each generation has a monotonic execution generation. Once a newer generation, deletion, Undo, Redo, or explicit replacement advances the owner revision, an older completion cannot mutate the current workflow-node owner. It may independently establish a history owner when product semantics require it. History failure does not roll back a successful node transition; the result remains under a retryable temporary owner. A user cancellation prevents an uncommitted result but never reverses an already committed transition implicitly.

Garbage collection and owner creation coordinate on the asset row. The last-owner release, first-owner creation, and zero-owner quarantine transition use an atomic lock or compare-and-swap plus unique reference constraints. GC takes a fenced reclamation lease and rechecks zero owners before marking quarantine. An owner arriving during quarantine first restores the verified asset. Database state `quarantine_pending` makes a failed physical move retryable, and restoration conflicts never overwrite different content.

Concurrent identical content is published from verified temporary files through a content-address uniqueness constraint; losers reuse the published asset and establish independent owners. Multiple coordinators may lease transition records, but every stage commit remains fenced by lease token, owner revision, storage epoch, and CAS. A paused or stale worker therefore cannot commit after lease expiry. Clients retry only transient pre-persistence failures with the original idempotency key; once recorded, one coordinator owns stage recovery.

Physical collection is guarded by a persistent per-store safety state: `healthy`, `scan_required`, `scanning`, `gc_suspended`, or `repair_required`. Startup performs only bounded structural checks before opening the editor. First use, timeout, unclean destructive work, an unreadable state pointer, a changed scanner version, or any uncertain result keeps collection disabled. Restart, dismissal, retry exhaustion, or user cancellation never resets the guard to healthy.

While guarded, every path that can move or physically delete media is disabled, including quota and manual cleanup, startup collection, quarantine expiry, and final migration-owner release. Normal browsing, editing, saving, generation, owner establishment, explicit recovery, and logical consumer deletion continue where storage permits. Released assets accumulate only as protected, recomputable zero-owner candidates.

The full integrity scan is low-priority, paged, rate-limited, and resumable. Its durable checkpoint binds scanner and report schema versions, storage epoch, stable per-source cursors, completed partition revisions, damage counts, and a rescan set. Each partition is validated again before publication; concurrent changes invalidate that partition, and persistently active workflows may use only a brief partition-level write barrier. One leased coordinator scans a storage epoch, while report publication remains fenced by epoch and safety-state compare-and-swap.

Only evidence-preserving repairs may run during scanning, transactionally by Workflow identity, and every repaired partition is rescanned. Scanner errors preserve their exact stage and retry with bounded backoff; unreadable databases, unknown schemas, unsafe paths outside the normalized media root, or unverifiable checkpoints require repair. Low disk uses reserved diagnostic capacity and sheds low-priority success detail, never unknown media or unresolved evidence.

Returning to `healthy` atomically publishes a complete current report and changes the safety state only after all four evidence sources are covered at valid revisions, safe repairs are reverified, pending transitions and liveness-threatening damage are resolved, quarantine is valid, and candidates are rechecked. A Missing Media asset with an unambiguous retained identity need not keep global collection suspended. Re-enabling collection merely permits the existing canary, limit, quarantine, and circuit-breaker process; it never immediately drains the backlog.
