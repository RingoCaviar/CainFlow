# Separate persistent and runtime Media asset ownership behind one transition module

CainFlow will classify Media asset owners by node semantics: `ImagePreview` uses a temporary runtime owner, while `ImageGenerate`, `ImageImport`, `ImageResize`, `ImageSave`, `ImageCompare`, and `ImageMerge` use persistent owners driven by the workflow document's Media asset reference list. One ownership transition module will own the intent operations, generation and revision checks, storage epoch fencing, transition recovery, and release ordering; callers will not assemble those coordination fields or mutate references directly. A persistent commit succeeds before its temporary owner is released. Partial success retains extra references and records `needs_reconciliation` for recovery instead of rolling back a required persistent reference. Existing storage, garbage-collection, migration, and CAS protections remain in force; callers migrate incrementally and direct `referenceMediaAsset`/`removeMediaReference` paths are removed after their replacements are covered by interleaving and recovery tests.
