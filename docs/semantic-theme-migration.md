# 语义主题皮肤迁移指南

设置面板试点确立了唯一权威边界：主题文件只提供可复用的语义调色板值，feature 皮肤负责组件选择器、结构和交互状态。后续迁移不得在主题文件中新增 feature DOM 选择器，也不得用 `!important` 恢复双重权威。

## 固定迁移顺序

1. 通用菜单和弹窗
2. 历史和缓存
3. 相机和工具控件
4. 节点和画布

每个组件族完成收缩与验收后，才开始下一个组件族。

## 每个组件族的 expand-contract 流程

1. 盘点现有主题限定规则、真实 DOM 状态和跨组件复用的视觉角色。
2. 在共享主题调色板中补充必要的语义角色，避免角色名称包含具体 feature 或主题名称。
3. 建立或扩展 feature 皮肤，由它统一消费语义角色并覆盖 normal、hover、focus、disabled、error 等适用状态。
4. 使用真实浏览器 fixture 验证七主题状态矩阵、弹层层级、代表性文本对比度和键盘焦点。
5. 删除该组件族的主题限定规则、临时 fallback 和迁移基线，并增加“不得重新命中该 feature DOM”的源码护栏。
6. 运行组件测试、视觉与无障碍验证、应用回归测试，再完成 Standards 与 Spec 双复审。

## 例外门槛

只有无法通过共享语义角色表达的主题标志性效果才能成为例外。例外必须局部化，记录共享皮肤不足的具体原因，并拥有针对性的真实浏览器视觉覆盖；缺少任一条件都应扩展语义契约，而不是保留主题限定组件规则。

## 2026-10 七主题配色修正

`theme-color-audit#001` 修正现有皮肤中的失效变量和可读性遗漏，不宣称未迁移组件族已经完成全面迁移。新增 `text-link`、`text-success`、`text-warning`、`text-danger`，由各主题已有正文与强调色混合得到，专供彩色文字和焦点使用；填充按钮继续使用 `panel-primary-action-bg/text`，不能把填充色直接当作小字颜色。

运行和主操作按钮的填充与文字由公共按钮组件统一负责，主题保留既有边框与阴影效果。协议编辑器消费共享调色板，其按钮颜色不能影响外部控件。更新通知取消按钮不再由各主题分别修补。Agent 浮层使用主题面板颜色叠加画布底色，保证下面的文字不透出；玻璃主题的其他材质效果保持。

验证、复现记录与本地截图见 [七主题配色 QA](qa/ui-theme-colors.md)。

## Agent 选择菜单统一（theme-color-audit#002）

联网方式与对话、生图、专用搜索、步骤模型共用 Agent select 适配器。原 select 保留值和事件契约；适配器只负责展示与用户选择，不推断模型、不提交设置。`selects` 兼容直接传元素，也接受 `{ select, parent, placeholder }`；`refresh()` 用于程序恢复值后的显示同步，不发出 change；`destroy()` 移除浮层、监听和观察器并恢复原生控件的可访问属性。

父浮层身份显式传入并交给 Surface coordinator，联网父层按归属标记识别子菜单，不再绑定某个模型菜单 ID。所有 Agent 菜单外壳使用公共 menu 语义角色；独立加载 Agent 皮肤的测试或宿主可回退到这些角色对应的 panel 调色板。命令、节点提及、参考图保留各自的布局和选择语义。箭头归触发按钮所有，避免不同宿主分别绘制或重复绘制。
